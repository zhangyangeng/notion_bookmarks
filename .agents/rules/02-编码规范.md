# 编码规范

## 一、格式化（由工具强制，不要手工调整）

**统一 2 空格缩进。** 由 prettier 强制执行，配置文件为 `.prettierrc`，编辑器通用规则见 `.editorconfig`。

```bash
pnpm format         # 全量格式化
pnpm format:check   # 仅检查，不写入
```

关键约定：

| 项 | 值 |
| :--- | :--- |
| 缩进 | **2 空格**（不支持 tab） |
| 引号 | 单引号（JSX 属性用双引号） |
| 分号 | 保留 |
| 单行宽度 | 100 字符 |
| 行尾 | LF |

> **背景**：改造前项目里 2 空格与 4 空格混用（`LinkCard.tsx` 是 2 空格，`notion.ts` / `types/notion/*` 是 4 空格），
> 根因是不同 AI 工具各写各的。已统一为 2 空格，**新代码一律按格式化结果来，不要手工对齐**。

## 二、TypeScript 约定

`tsconfig.json` 已开启 `strict` / `noUnusedLocals` / `noUnusedParameters` / `noImplicitReturns`，另加以下要求：

- **严禁 `any`。** 需要"任意类型"时用 `unknown` + 类型收窄（`typeof` / `in` / 自定义守卫）。
- **导出的函数显式标注返回类型**，避免推断结果意外外泄成为隐式契约。
- **组件必须声明 props 接口**，不要用内联对象类型散落各处。
- **禁止在类型层写副作用代码**（`src/types/**` 只放类型与枚举）。
- 路径别名统一用 `@/*`（映射到 `./src/*`），不要写 `../../..` 长相对路径。

## 三、注释

- 注释解释**"为什么这样设计"**，不解释"是什么"。代码本身能说明"是什么"。
- Class / Interface / Type / Enum / 函数**必须有注释**；`//` 与内容之间留一个空格。
- 关键位置用统一标记：`NOTE`（需注意的设计取舍）、`TODO`（待办）、`FIXME`（已知缺陷）。

```ts
// NOTE: 用原生 img 而非 next/image，避免消耗 Vercel 图片优化额度
```

## 四、Next.js / React 约定

### 服务端优先

- **默认写 Server Component**，不轻易加 `'use client'`。
- `'use client'` 只加在真正需要交互、状态或浏览器 API 的组件上（如 `MainContent.tsx`）。
- 数据获取放在服务端（`src/lib/notion.ts`），不要在客户端组件里直接调 Notion —— 会暴露 Token 且拖慢首屏。

### 缓存

- **缓存开关只认路由段的 `export const revalidate`。** 环境变量、模块常量都不会生效（项目里曾有过这种死代码）。
- 需要按需刷新时用 `revalidateTag` / `revalidatePath`，并配独立的触发路由。

### 组件

- 纯展示组件用 `memo` 包裹，并写**明确的比较函数**（只比真正影响渲染的字段），不要用默认浅比较。
- 列表渲染的 `key` 用稳定 ID，不用数组下标。

## 五、本项目特有约束

### 1. 图标：禁止全量导入

```ts
// ❌ 会把整个图标库打进产物
import * as Icons from 'lucide-react'

// ✅ 具名导入
import { Rocket, ChevronDown, Globe } from 'lucide-react'
```

项目里同时存在 lucide、`@tabler/icons-react`、`@radix-ui/react-icons` 三套图标库，
**新增图标前先确认已有的能否复用**，不要再引入第四套。

### 2. 定时器：禁止轮询

图片/异步状态的完成检测用 `onLoad` / `onError` 事件，**不要用 `setInterval` 轮询 `image.complete`**。
历史上每张卡片挂 2 个 1 秒定时器，200 张卡片就是数百个定时器同时跑 —— 这是滚动卡顿的主因。
超时降级只能用**单次 `setTimeout`**，且必须在 cleanup 中 `clearTimeout`。

### 3. Notion 调用必须集中在 `src/lib/notion.ts`

组件层不直接接触 `@notionhq/client`。字段转换、图标 URL 解析等脏活都在 `lib` 层做完，
组件只消费干净的业务类型。

### 4. 改样式前先确认主题结构

主题样式集中在 `src/themes/**`，组件里可能存在 `theme === 'xxx'` 这类分支。
**动手前先确认主题有几套、分支如何分布** —— 否则同一个改动要在多处重复，且容易漏改。

## 六、命名与目录

- 组件文件：`PascalCase.tsx`（`LinkCard.tsx`）
- 工具/逻辑文件：`kebab-case.ts`（`link-icon.ts`）
- 目录：小写短横线（`link-container`）或语义化复数（`components/ui`）
- React 组件：`PascalCase`；hooks：`useXxx`；常量：`UPPER_SNAKE_CASE`
