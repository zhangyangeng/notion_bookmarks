# 项目结构

本项目是 **Next.js App Router 单栈工程**（前后端同仓，无独立后端服务）。
新增代码请严格按目录职责归类，**禁止在根目录或 `src/` 顶层随意创建新目录**。

---

## 一、工程树与职责

```text

│

│   │   ├── page.tsx                # 首页（**ISR 缓存开关在此**）

│   ├── config/                     # 站点默认配置（Notion 读取失败时的兜底值）
│   ├── themes/                     # 主题样式与注册表
│   │   ├── theme.css               # 基础变量 + 各主题样式汇总
│   │   ├── registry.ts             # 主题注册表

│   └── types/                      # 类型定义层（**只放类型，禁止副作用代码**）
│       ├── notion/                 # Notion API 的字段与转换类型
│       ├── api/                    # 接口响应类型
│       └── *.d.ts                  # 第三方库缺失的类型补充

├── .editorconfig                   # 编辑器通用格式规则
├── .prettierrc                     # 格式化配置（2 空格）

└── package.json                    # 依赖与脚本
```

## 二、分层约束

### 依赖方向（单向，禁止反向引用）

```text
app/  ──→  components/  ──→  lib/  ──→  types/
                              ↓
                           config/
```

1. **`app/`**：只负责路由、页面组装与缓存声明。接口路由不写业务逻辑，转调 `lib/`。
2. **`components/`**：只关注渲染与交互。**不直接调用 Notion 或外部 API**，数据由上层传入或经 `lib/` 获取。
3. **`lib/`**：业务逻辑与外部服务适配。所有 Notion 调用、字段转换、图标 URL 解析都在这里完成。
4. **`types/`**：纯类型层，禁止包含运行时代码与副作用。
5. **`config/`**：兜底配置值，不参与业务编排。

### 单一职责

- `lib/utils.ts` 只放**与业务无关**的纯函数（格式化、字符串处理）。有业务语义的函数放到对应模块（如 `lib/category.ts`）。
- 一个组件文件只导出一个主要组件，避免"文件即杂货铺"。

### 路径别名

统一使用 `@/*`（映射 `./src/*`）：

```ts
import LinkCard from '@/components/ui/LinkCard'
import { getLinks } from '@/lib/notion'
```

## 三、新增代码该放哪

| 你要写的东西 | 放这里 |
| :--- | :--- |
| 新页面 / 新接口 | `src/app/**` |
| 可复用的纯 UI 组件 | `src/components/ui/` |
| 页面骨架类组件（导航、容器、页脚） | `src/components/layout/` |
| 数据获取 / 字段转换 / 外部服务适配 | `src/lib/<模块>.ts` |
| 类型与接口定义 | `src/types/**` |
| 兜底配置项 | `src/config/index.ts` |
| 主题样式 | `src/themes/<主题名>/` |
| 单元测试 | 与被测文件同目录，命名 `*.test.cts` |
| 决策文档的配套可视化（配色 Demo、示意图） | `docs/assets/` |

## 四、动手前：确认目标是否在移除计划中

**动手前先确认目标文件是否在移除计划内** —— 清单见 `docs/architecture/02-改造路线.md` 的减法清单。

凡被列为移除目标的内容，**不要为其写新功能、做优化，或在新代码里引用**。
判定依据与理由同样在该文档中，此处不重复（避免两处维护、各自过期）。
