# 界面设计

> 本文档回答界面**长什么样**、**为什么这么设计**：设计令牌、玻璃体系、布局与交互的长期约定。
> 定位与数据模型见 [`01-产品定位与架构设计.md`](./01-产品定位与架构设计.md)；
> 改什么、按什么顺序改见 [`02-改造路线.md`](./02-改造路线.md)。
>
> 视觉令牌以 `src/app/globals.css` 为准，本文只固定那些**长期成立的设计原则**。

---

## 一、设计取向

| 取向 | 含义 |
| :--- | :--- |
| **夜读感，不是科技感** | 深米色页 + 墨绿字，像翻一本私人笔记。避开紫蓝渐变那类「AI 风」 |
| **一冷一暖** | 主色墨绿偏冷沉，另配暖赭 `--warm` 给需要提亮的元素（推荐标签）加活力 |
| **信息密度优先** | 头号目标是「描述看得见」—— 宁可少一列，也要横向卡片 + 3 行描述 |
| **玻璃是点缀，不是底** | 只用在侧栏 / 搜索面板 / 底部条 / 回到顶部这几处；卡片网格不用重玻璃 |
| **动效克制** | 全部纯 CSS，只动三处；`prefers-reduced-motion` 下一律关闭 |

## 二、设计令牌

明暗由 `next-themes` 的 class 策略驱动：浅色写 `:root`，深色写 `.dark`。

### 2.1 配色

| 令牌 | 浅色 | 深色 | 用途 |
| :--- | :--- | :--- | :--- |
| `--background` | `245 244 238` | `29 33 31` | 页面底色（暖白 / 深墨） |
| `--foreground` | `42 49 44` | `231 235 230` | 正文 |
| `--card` / `--popover` | `251 250 245` | `36 41 36` | 卡片与浮层 |
| `--primary` | `63 92 74` | `147 184 155` | 主色（旧墨水绿）：选中态、强调、滚动条 |
| `--muted-foreground` | `99 106 99` | `169 178 171` | 次级文字 |
| `--border` | `40 60 45` | `255 255 255` | 边框基色（实际用 `<alpha-value>` 调透明度） |
| `--warm` | `176 137 74` | `214 178 122` | 暖赭点缀 |
| `--glass-bg` | `rgba(251,250,245,.72)` | `rgba(36,41,36,.72)` | 玻璃面底色 |

> **变量值必须是 RGB 三元组**（`63 92 74`），tailwind 侧写成 `rgb(var(--primary) / <alpha-value>)`。
> 写成完整颜色值（`rgb(63,92,74)`）会让 `bg-primary/10` 这类透明度修饰符不生成任何 CSS。
>
> 主色 `63 92 74`（旧墨水绿）是在七套候选配色里选定的。候选全貌（初版三选 + 墨绿细化四档）与选定过程见
> [`assets/ui-theme-demo.html`](../assets/ui-theme-demo.html) —— 可直接切换配色、明暗与光斑，页面顶部实时显示各配色的令牌值。

### 2.2 圆角

| 写法 | 值 | 用于 |
| :--- | :--- | :--- |
| `--radius`（`rounded-lg`） | `1rem` | 底部条、卡片 |
| `rounded-2xl` | `1rem`（tailwind 默认值） | 侧栏、移动端顶栏胶囊、抽屉顶角 |
| `rounded-nav` | `0.625rem` | 导航项、按钮等交互控件 |

> 导航项单独用更小的 `rounded-nav`：圆角过大时，选中态的左侧竖条会被圆弧两端裁短。
> 大玻璃面统一为 1rem，但当前由 `rounded-lg`（跟随令牌）与 `rounded-2xl`（写死默认值）两种写法表达 —— 改令牌时注意后者不会跟着变。

### 2.3 字体

系统字体栈（`--font-sans`），不加载任何 Web Font：国内零下载、零阻塞。

## 三、玻璃体系

**前提：玻璃必须压在非平背景上。** `body` 铺三块 `background-attachment: fixed` 的径向光斑（墨绿 / 古铜 / 青灰），玻璃的 rgba 底色才有东西可透。若把玻璃放在纯色底上，`backdrop-filter` 模糊前后没有差别，读起来就是一块塑料。

光斑的几何形状决定玻璃能否透出背景色 —— 实测表明其影响远大于玻璃自身的不透明度。主斑是一块竖长墨绿椭圆，横跨侧栏与内容区左半；参数取值、实测数据与换项目的复用方法见 [`docs/references/03-背景光斑布光.md`](../references/03-背景光斑布光.md)。

三级配方，按使用面积递减、成本递减：

| 类 | 用于 | 强度 |
| :--- | :--- | :--- |
| `.glass-surface` | 侧栏、搜索面板、详情弹层、底部条、主题弹框、移动端顶栏与抽屉 | `blur(20px) saturate(180%)` |
| `.glass-card` | 全部卡片 | `blur(8px) saturate(140%)` |
| `.glass-brilliant` | 回到顶部按钮 | `blur(18px)` + 主题染色底 + 柔光 + 掠光 |

`glass-card` 刻意「更实、模糊更弱」：它的用量最大，每张卡都背高成本 blur 会明显掉帧。

### 3.1 `glass-brilliant` 的四层叠加

只给 `backdrop-filter` 而自身底色透明时，玻璃是**看不见的** —— 必须给足自身底色与高光才有实体感。四层叠加：

1. 主题染色渐变底（暖白 → `--primary` 染色 → 暖白）
2. 左上柔光 `::before`（`z-index: -1`，落在自身背景之上、图标之下）
3. 上下内描边（顶亮边 + 下缘收暗）
4. 掠光 `::after`：常态 5.5s 缓行、悬停一趟快掠

**配色必须留在墨绿家族内**：底色取暖白（深色取深灰绿），中段压一层 `--primary` 染色给出主题色相，高光由「镜面」降为「柔光」（约 0.72）。镜面级高光（0.95+）在这套界面里会读成塑料珠，与其它玻璃面不是一家人。

## 四、布局与组件

### 4.1 侧栏（桌面）

| 态 | 宽 | 内容 |
| :--- | :--- | :--- |
| `expanded` | 280px | 标题 + 搜索框 + 分类树（图标 / 名称 / 计数 / 展开箭头） |
| `icons` | 64px | 仅图标 + 计数，`title` 悬停显示分类名 |

- 浮起面板：`left-3 top-3 bottom-3` + 玻璃面，宽度走 `transition-[width]`。
- 状态存 `localStorage`（`nav.sidebar-state`）。**首帧恒为展开态**，真实值在 layout effect 里补齐 —— 渲染期直接读 storage 会与 SSR 输出不一致，触发 hydration 报错。
- **没有「彻底隐藏」态。** 侧栏是唯一的主导航，隐藏后只留一个召回的图标占位，收益为负。
- 选中态：`bg-primary/10` + 左侧 2px 竖条，不再整块反白。
- 二级分类挂在展开的一级之下，用 `border-l` 引导线表达从属关系；二级选中**只加深文字**，不叠背景 —— 一级已有竖条与背景，二级再叠会夺走层级焦点。
- 每个一级分类带计数 badge，不展开也知道这组多大。

**两态的元素高度与内边距必须严格对齐**，否则切换时下方分类列表整体上下跳动。具体做法：顶部区钉死 `h-[122px]`；侧栏两态统一 `p-2`（padding 跟着状态变会把内容连续推着平移）；展开态各块钉死 `w-[248px]` 并让容器 `overflow-x-hidden` 裁切 —— 折叠动画期间容器窄于内容，文字若不钉宽就会折行（高度 48→24 抖动）。

### 4.2 移动端与平板

- **< md**：顶部浮起胶囊条（logo + 搜索 + 主题 + 分类按钮），分类走**底部抽屉**（`rounded-t-2xl` 玻璃面 + 半透明遮罩）。
- **≥ md（含平板）**：走桌面侧栏，不为平板另做一套布局。

### 4.3 卡片

左图标（56px）右内容的横向布局，`min-h-[120px]`；桌面 3 列（`2xl` 放宽到 4 列），移动 1 列。

| 项 | 取值 |
| :--- | :--- |
| 标题 | `text-base font-semibold`，最多 2 行 |
| 描述 | `line-clamp-3` —— 头号目标：描述要看得见 |
| 标签 | 最多 3 个 + `+N`；`推荐` 走暖赭强调样式 |
| hover | `-translate-y-1` + `scale-[1.01]` + 阴影 |

图标容器不铺底色：异形 logo 不再顶着一个方块。

卡片右下角另有常驻的「详情」入口（见 4.8）。它**不是官网链接的一部分**，而是与之并列的独立按钮 —— 点卡片任意处仍然直接开官网。

### 4.4 底部条

`fixed bottom-3 left-0 right-0` 横向铺满，**内条 `mx-4`** 与内容区 `px-4` 对齐 —— 玻璃条宽度必须与卡片列一致，否则两者左右错开、同一圆角在两块不同宽度的矩形上观感也不同。单行布局：版权在左、社交图标在右，中间一条 `w-px` 细分隔线。

版权年份由 `src/lib/copyright.ts` 统一：起始年写死 `2025`（此前提交属上游模板作者），结束年取当前年，区间显示为 `2025–2026`。**年份在服务端计算后当 prop 传下来**，客户端不参与计算 —— 客户端取当前时间会与 ISR 缓存的 HTML 不一致。

社交位图图标（即刻 / 小红书）常驻 `grayscale`，与同排 FontAwesome 图标的灰度对齐；悬停压暗而非还原彩色。

### 4.5 搜索面板

`Cmd/Ctrl + K` 唤起，面板走 `.glass-surface`。快捷键符号**按系统渲染**（macOS 显示 `⌘`，其余 `Ctrl`），首帧不判平台（返回 `null`）以免 hydration 不一致。键帽拆成两个等宽 `.kbd` 居中 —— `⌘` 是符号、`K` 是字母，直接并排会一大一小。

### 4.6 回到顶部

右下角 44px 圆形按钮，`glass-brilliant` 配方。两条约定：

- **出现阈值取「视口高度 20%」与「160px」的较大值。** 固定像素阈值在短页上永远达不到，按钮根本不出现。
- **底部偏移随路由切换**：首页让位浮起的底部条（`bottom-[68px]`），分享页贴底（`bottom-3`）。分享页没有那条，沿用同一让位值会让按钮悬在半空，扫一眼会以为它不存在。

### 4.7 分享页 `/c/[slug]`

- **不铺背景色** —— `body` 的墨绿光斑要透上来，卡片的 `backdrop-filter` 才有东西可糊。
- 卡片复用与首页同一套玻璃配方和圆角。
- 底部一行居中署名（`© 2025–2026 … · 保留所有权利`）。读者从外部链接进来、并不认识这个站，署名在这里比在首页更有用；但排版保持轻量，不复制首页那条浮起玻璃条 —— 那是导航辅助，不是内容。技术署名只留在首页。

### 4.8 链接详情弹层

卡片单击**仍然直接跳官网**，一步不变；卡片右下角另有一个常驻入口，点开才是详情。

| 项 | 取值 |
| :--- | :--- |
| 入口形态 | 静止时一粒淡点；指针悬停 / 键盘聚焦展开为「详情」胶囊 |
| 移动端 | 没有 hover，直接用那粒淡点的常驻态 |
| 显隐条件 | **常驻，不依赖数据判断** —— 每张卡都能点开 |
| 桌面 | 居中面板，`max-h-[70vh]`，内部滚动 |
| 移动 | 底部抽屉 |
| 两态实现 | **同一套 DOM，靠响应式类名切换**，不写两套 |

入口不做数据判断，既不需要知道「这条有没有补充内容」，也不必在数据变化时同步显隐状态。

#### DOM 结构（长期约定）

`<a>` 的内容模型不允许交互元素后代，所以入口不能嵌在官网链接里。两者并列：

```text
div.relative.group     ← 定位、hover 反馈、入口展开所依赖的 group 锚点都在这一层
├── a          铺满整卡，单击直接跳官网
└── button     绝对定位在右下角，独立点击通道
```

> 卡片最后一行由「标签 + 入口」共用（`.card-detail-band`）：带高取入口高度 `1.5rem`，锚点底部只留 `0.5rem`，于是入口与标签行落在同一区间 —— 齐平，不各占一行。标签区右侧留 `2.75rem` 净空，正好是入口展开后的宽度：滑出「详情」时落在净空里，压不到标签。
>
> 让位只发生在标签区，描述所在区域分毫不减。给正文加横向内边距的话，长描述的最后一行会被逼着折行 —— 而那一行正是入口展开时会扫过的地方。

hover 的位移与缩放挂在这一层，不挂锚点 —— 挂在锚点上时，指针移到入口按钮上，锚点不再是悬停目标，
卡片反馈会消失，入口也会收回去。

**以后往卡片上加任何交互元素，都按这个结构挂。**

#### 三段结构

| 区 | 内容 | 行为 |
| :--- | :--- | :--- |
| 头部 | 图标 + 标题 | 固定 |
| 中部 | 描述全文 + 点评 + 补充内容 | 可滚动 |
| 底部 | 「访问官网」 | **固定**，内容再长也随时可点 |

描述在卡面被 `line-clamp-3` 截断，点评在首页压根不显示 —— 所以**每张卡点开都有比卡面更多的内容**，弹层不是只为「有补充内容的卡」服务的。

#### 数据来源分层

| 内容 | 来源 | 点开时 |
| :--- | :--- | :--- |
| 标题 / 描述 / 点评 / 标签 | 列表数据（属性） | 立即渲染 |
| 补充内容（页面正文） | 按需向服务端请求 | 到位才渲染 |

**补充内容为空时该区块整块不渲染**，不显示任何占位文案。
**等的过程也一样不渲染任何东西 —— 没有骨架屏。** 多数条目本来就没有正文，加载提示在它们身上的结局只是「出现又消失」，请求越慢这场空演得越完整，观感比从头到尾没有更割裂。让「还在路上」与「本来就没有」表现一致：都是空白，正文回来才长出来。

#### 浮层配方

沿用搜索面板：`fixed inset-0` + `bg-black/40 backdrop-blur-sm` + `.glass-surface` 面板 + 点遮罩关闭 + `Esc` 关闭。
**面板自身的滚动锁要补上** —— 详情内容比搜索结果长得多，背景跟着滚会很别扭。

### 4.9 分类锚点与地址栏

首页的分类导航与地址栏共用一套锚点，一级、二级各有自己的位置：

| 位置 | 锚点 | 例 |
| :--- | :--- | :--- |
| 一级分类 | `#<一级短名>` | `#dev` |
| 二级分类 | `#<一级短名>/<二级短名>` | `#dev/tools` |

- **短名取自分类库的 `Slug` 字段**。一级短名充当命名空间，二级短名只要求在自己一级内唯一。未填短名的分类退回记录 id —— 链接会变长，但不会失效；分类改名不断链。
- **地址栏与 DOM 解耦**：DOM 仍是 `section#<一级id>` / `div#<一级id>-<二级id>`（`subCategoryAnchorId`），地址栏写短名、内部定位用记录 id，换算集中在 `src/lib/category.ts`。
- **锚点用 hash 承载**。它不发给服务端，切换分类不重新请求页面，也不经过路由。

三条写入路径都集中在内容区组件，侧栏只上报点击意图：

| 触发 | 写入方式 |
| :--- | :--- |
| 点击侧栏分类 | `pushState` —— 记一条新历史，可逐步后退撤回 |
| 滚动浏览 | `replaceState` —— 覆盖当前条目，不堆历史 |
| 视口回到页顶 | 清掉锚点 —— 此时不在任何区块上，留着会让复制出的链接指向错位置 |

两条必须守住的约束：

- **落位期间要暂停滚动同步。** 切换分类会平滑滚过多个区块，此刻监听若跟着改写锚点，会把刚写入的目标覆盖成中途路过的那个。这把锁必须用**不依赖 effect 生命周期**的形式（当前为解锁时刻的时间戳）—— 滚动监听的 effect 会在切换分类时重建，任何存在 `ref` 里的定时器都会被重建时的清理函数一并清掉，解锁从此再不会发生，滚动同步静默失效。
- **滚动偏移只由 CSS 提供**（`html { scroll-padding-top }`），组件里不再叠加偏移量。同一个偏移两处各写一遍，迟早会漂。

另有一条体验约定：**带锚点的链接用 `instant` 落位**，中途不出现从页顶滑下来的动画 —— 直接打开链接的人只想立刻看到那块内容。

## 五、动效

| 处 | 实现 |
| :--- | :--- |
| 卡片进场 | `.card-enter` 错位淡入，延迟 = 序号 × 40ms（CSS 变量 `--i`） |
| 卡片 hover | `-translate-y-1` + `scale-[1.01]` + 阴影 |
| 侧栏折叠 | `transition-[width] duration-200` |
| 回到顶部 | `opacity` + `translate-y` 淡入；常态掠光 5.5s |
| 详情弹层 | 遮罩淡入 + 面板上浮 |
| 分类定位 | 滚动到目标区块后闪一次（`@keyframes highlight`） |
| 滚动条 | 墨绿细条（`scrollbar-width` / `::-webkit-scrollbar` 双通道） |

不依赖任何动画库。`prefers-reduced-motion: reduce` 下关掉进场与掠光动画，并撤掉 body 光斑。

## 六、依赖

**不引入任何新库。** 复用已有依赖：图标走 `lucide-react` / `@tabler/icons-react` / `react-icons`（全部按需具名导入，不用 `import *`），类名合并用 `clsx` + `tailwind-merge`，明暗用 `next-themes`，滚动条用 `tailwind-scrollbar` 插件。

> ⚠️ **2026-09-14 修正：「按需具名导入」不再适用于分类图标。**
> 一级分类的图标改为在服务端解析（`resolveCategoryIcon`），客户端只渲染解析结果、不再持有图标表格，

## 七、明确不做

- **卡片内联展开内容。** grid 的行高由该行最高的卡片决定，一张卡展开会把同行邻居一起撑高；长内容在卡片里也没有可读性。补充内容走详情弹层（见 4.8）。
- **小组件**（时钟 / 天气 / IP / 热搜 / 自选股）。与定位无关，铁律 4 仍生效。
- **第二套设计语言。** 只保留墨绿一套，明暗两版。
- **隐藏侧栏态。** 已移除，不再加回（见 4.1）。
- **给卡片网格铺重玻璃。** 整页卡片同时 blur 的掉帧换不来观感收益。

## 八、与原方案的取舍记录

界面方案曾有一版「暖琥珀 + 深靛」的配色与几项不同的做法，落地时改了主意。记在这里，避免被重新提起：

| 项 | 原方案 | 落地 | 原因 |
| :--- | :--- | :--- | :--- |
| 配色 | 暖琥珀 + 深靛 | **墨绿米白 + 暖赭** | 琥珀与深靛一暖一冷，搭起来像「主题配的色」；墨绿米白更接近私人笔记的气质 |
| 侧栏底部 | 保留原「固定贴底条」不动 | 重做为浮起单行玻璃胶囊 | 与侧栏同一套语言，且单行比两行省空间 |
| 卡片进场 | 纯 CSS + `IntersectionObserver` 触发 | 只留纯 CSS 错位延迟 | 首屏卡片本就要立即出现，交点触发没有实际收益 |
| 背景光斑 | 三块大光斑（左上 / 右上 / 下中），未覆盖侧栏正后方 | 分区布光，主斑为竖长椭圆、横跨侧栏与内容区 | 原光斑不在玻璃面正背后，玻璃透不出绿；光斑形态比玻璃透明度影响更大（见 [`03-背景光斑布光`](../references/03-背景光斑布光.md)） |
