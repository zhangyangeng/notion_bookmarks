## 一、方法

不靠推断，靠比对。上游作者至今仍在线运营 Demo 站，等于提供了一份**权威的「原始快照」**：

```
上游 Demo：  https://portal.ezho.top/api/links      → 198 条
本项目线上：  https://nav.wrysmile.cn/api/links     → 221 条
比对维度：    URL（归一化：去协议 / 去 www / 去尾斜杠 / 去 query）
             + 名称 + 创建时间 + 标签
```

> 之所以能用「抓数据」代替「读代码推断」：本项目的公开接口 `/api/links` 可直接返回全量 JSON，上游 Demo 同理。
>
> ⚠️ **2026-09-12 修订**：`/api/links` 现已加可见性白名单，只返回 `公开` 条目（执行下述审计时为 221 条全量）。复现本节结论需直查 Notion，不能再用这个接口。

## 三、四条铁证

### 证据 1 · 全部创建于同一个月

继承的 184 条，`created` **全部落在 2025-07**。这不是「参考」，是**一次性整库复制**的行为特征。

### 证据 2 · 作者痕迹仍留在库里

```
[开发资源/效率工具]  WildCard  →  https://yeka.ai/i/EZHO    ← 带作者返佣码
[开发资源/效率工具]  Ezho      →  https://ezho.top/         ← 指向作者本人博客
```

第二条尤其直白：**这个导航站里有一条指向「原作者博客」的链接。**

| 标签 | 本项目 | 上游 Demo |
| :--- | :--- | :--- |
| `力荐👍` | 18 | 15 |

## 四、这个库的真实身份

把三层叠起来：

```text
nav.wrysmile.cn  =
     别人的门户（83%）
   + 自己用的技术文档书签（17%）
   + 想分享给朋友的内容（0%）   ← 全在博客里，没进来
```

**所以这个站对谁都不成立：**

| 面向 | 为什么不成立 |
| :--- | :--- |
| **对朋友** | 他要的（图床、Win 工具）一条没有；打开看到的是 AI 工具和开发资源，与他的问题无关 |
| **对自己** | 用 Notion 存前端文档书签，不如浏览器收藏夹顺手 |
| **对搜索** | 内容是抄的，没有存在意义 |

**这不是「界限不清」的问题，是起点错了** —— fork 时把「别人的成品」当成了「自己的草稿纸」，然后一直在给一份不属于自己的稿子做本地化改版。

## 五、上游活跃度（判断是否跟随的依据）

上游 Demo 的 198 条按创建月份分布：

| 时期 | 新增 |
| :--- | :--- |
| 2024-12 ~ 2025-05 | **169 条（主力期）** |
| 2025-06 之后 | 急剧衰减 |
| 2026 全年 | **仅 4 条** |

**上游已进入准停滞状态，跟随它没有价值。**

这意味着两件事：

1. **内容层面：停止同步** —— 要清理的正是这 184 条。
2. **代码层面：停止 merge，但保留只读通道** —— 改造方向与上游的更新方向是**相反的**（本项目在做减法，上游 v0.2 / v0.3 在做加法：加主题、加天气组件）。merge 上游等于把刚删掉的东西装回来。

   > 但「不同步」不等于「再也不看」。建议保留 `upstream` remote，每隔几个月 `git fetch upstream` **只看**有没有 `fix` / `security` 类提交，有的话手动 cherry-pick 那一个 commit，不做整体同步。
   > 这条通道是必须的 —— 分家的代价是 **bug 修复从此自己扛**。
